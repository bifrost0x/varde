Versions and releases

Each switch says who learns what before you turn it on. All are off by default.

{{template "csrf" $csrf}} For containers started from tags such as latest: Varde reads the tag list of the image's repository and compares the digests of release tags with the running one, anonymously and read-only. It also reads the tag list of every other image the data package brings no release tags for (your own registries, images outside the catalog), so the inventory can say when a newer release exists. The registry learns which images you run, as it does when you pull them.
{{template "csrf" $csrf}} Once per image and week, Varde reads fixed files from one of its containers: /etc/os-release (or /usr/lib/os-release), /var/lib/dpkg/status and /lib/apk/db/installed. It also reads the package.json in the image's working directory and its parent. An app installed from its project's own package, or shipping its own manifest, gives its version this way. Agents read the images of their own containers the same way. With the osv.dev source on, the packages of each image are also checked against their distribution's security data. Nothing else is read.
{{template "csrf" $csrf}} Shows when the release line an app runs stops getting fixes, for apps endoflife.date tracks (nginx, Nextcloud, Traefik, Caddy, Proxmox, authentik). Reveals these product names to endoflife.date, once a day.
