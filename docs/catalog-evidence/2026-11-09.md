# Catalog verification report (2026-11-09)

Read from upstream source at the latest release tags of that day, or from the vendors' package
repositories. Each value below is used in `catalog/apps/`.

## Version endpoints (`version.probe.http`)

| App | Endpoint | Version | Proof of product | Source |
|---|---|---|---|---|
| Jellyfin | `GET /System/Info/Public`, no `[Authorize]` | `/Version`, three parts (`12.4.0`) | `/ProductName` = `Jellyfin Server` | jellyfin/jellyfin v12.4 `Jellyfin.Api/Controllers/SystemController.cs`, `Jellyfin.Server/Properties/AssemblyInfo.cs` |
| Navidrome | `GET /rest/getOpenSubsonicExtensions?f=json`, the only public Subsonic route | `/subsonic-response/serverVersion`, `0.64.2 (<sha>)` | `/subsonic-response/type` = `navidrome` | navidrome/navidrome v0.64.2 `server/subsonic/api.go`, `server/subsonic/helpers.go` |
| Vaultwarden | `GET /api/version`, no guard; a JSON string `VW_VERSION` (`"1.37.5"`; `<tag>-<sha>` on custom builds, which the pattern rejects) | whole response | `GET /api/config`: `/server/name` = `Vaultwarden`. Its `version` is a fixed Bitwarden compatibility string and is not used | dani-garcia/vaultwarden 1.37.5 `src/api/core/mod.rs`, `build.rs` |
| Nextcloud | `GET /status.php` | `/versionstring` (`33.0.10`) | `/productname` = `Nextcloud`. A theme can change it; themed instances are then not identified, never misidentified | nextcloud/server v33.0.10 `status.php` |

Not added, because the response carries no field that proves the product: Immich
(`/api/server/version`, public, `{major, minor, patch}`), Portainer (`/api/system/status`,
`{Version, InstanceID}`), Traefik (`/api/version`, only with the API enabled; `Codename` is weak).
No unauthenticated version endpoint: Home Assistant (all `api` views require auth), Uptime Kuma
(version hidden until login), Paperless-ngx (`X-Version` only for authenticated requests).
