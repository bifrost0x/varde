# Catalog seed verification report (2026-11-08)

Raw evidence files (not retained in the repository): `adv.txt` (repo advisory counts), `advpkgs.txt`
(package names used inside repo advisories), `ghsa.txt` (GitHub global advisory DB counts),
`osvres.txt` (OSV API counts), `cpe.txt` / `cpe2.txt` (NVD CPE/CVE queries), `tools/hub*.txt`,
`tools/ghcr1.txt` (tag lists), `tools/lbl*.txt` (image labels).

## Methods

- Repo advisories: `gh api 'repos/OWNER/REPO/security-advisories?per_page=100' --paginate --jq length`
  (summed over pages). 0 covers both "404" and "none published".
- Global DB: `gh api 'advisories?ecosystem=<eco>&affects=<pkg>&per_page=100' --paginate`.
- OSV: `POST https://api.osv.dev/v1/query {"package":{"ecosystem":..,"name":..}}` (counts include
  GO-/PYSEC- aliases, so they are larger than GHSA counts).
- Labels: `docker buildx imagetools inspect <ref> --format '{{json .Image}}'`, linux/amd64 config.
  Docker Hub manifests hit the anonymous pull limit (100/h) midway; the remaining Hub-only images
  were inspected through `mirror.gcr.io/<ns>/<repo>` (Google's Docker Hub pull-through cache,
  same digests).
- Tags: Docker Hub API `v2/repositories/<ns>/<repo>/tags?ordering=last_updated`; GHCR
  `/v2/<repo>/tags/list` with anonymous token. GHCR anonymous token 403 = repository does not
  exist (used to confirm absent lscr.io images, cross-checked with `gh api repos/linuxserver/docker-<x>`).
- NVD: `cpes/2.0?keywordSearch=` and `cpeMatchString=`, `cves/2.0?keywordSearch=`, 7 s apart.
- Tag regexes were tested in Python `re` against real tags (constructs used are RE2-compatible:
  no lookaround, no backreferences, `(?P<v>...)` groups). Go was not available to test with RE2 itself.
- YAML validated with PyYAML: required fields, enums, id = filename, SPDX header, lowercase image
  matches, no duplicate images (lsio aliases normalised), oci_source format, anchored regexes with
  group `v`, CPE format. No problems. `internal/catalog` and `catalog/schema.json` do not exist yet,
  at the time of research; they have since been validated by the authoritative loader (`go test ./catalog`).

## Open issues / uncertainties

1. Schema/loader behaviour not testable: no `internal/catalog` or `catalog/schema.json` in the repo yet. Assumptions: an unparseable label falls through to the next source (authentik legacy, open-webui `main`); `flavor: lsio` applies the normaliser without `normaliser: lsio` on the source item; a calver parser accepts zero-padded months (pi-hole) and rejects/handles `.devNNN` / `bN` suffixes (home-assistant).
2. Jellyfin `unstable` images: version label `2026110213` would be read as a real version. Needs a label-value filter or a per-source regex on labels.
3. Authelia and hotio source labels carry `/tree/<ref>`; oci_source matching needs normalisation.
4. Pi-hole: docker release version vs component advisory versions (set to partial).
5. Portainer CE vs EE version lines diverge; maybe split EE into its own app.
6. Nextcloud AIO not covered; advisories in nextcloud/security-advisories cover many products, need product filtering.
7. netbird: client image included in the same entry; dashboard excluded; ports for legacy split deployments not verified.
8. Not label-inspected because of the Docker Hub pull limit: paperlessngx/paperless-ngx, docker.n8n.io/n8nio/n8n, blakeblackshear/frigate (legacy), netbirdio/reverse-proxy (tags only). Their entries rely on the sibling GHCR image or the tag.
9. Frigate port 8971 and authentik ports 9000/9443, netbird 80/3478 come from docs/compose, not from ExposedPorts.
10. Coverage judgement calls: syncthing and sonarr partial (few advisories), linkwarden full with only 3 advisories.
11. Paperless homepage returned 403 to curl (bot protection), not browser-verified.
12. Regexes tested with Python `re`, not Go RE2.

## Follow-up after review

- Portainer Business Edition split into its own entry (`portainer-ee`, coverage limited) because its version line differs from CE; CE advisory ranges must not be applied to EE versions.
- OCI source labels with `/tree/<ref>`, `/commit/<sha>` or `/blob/` suffixes are normalised by the loader (Authelia, hotio images).
- linuxserver.io base-image suffixes (`12.4ubu2604-ls58`) are normalised before tag patterns are applied (Jellyfin).
- Pi-hole component advisories (FTL/web/core versions) do not parse as the image's calver scheme; comparisons are incomparable and yield `unverified`, never `affected`.
